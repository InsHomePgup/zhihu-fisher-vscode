# 风控优化方案

> 以下问题会导致知乎风控识别插件为爬虫行为，引发 Cookie 加速失效、内容降级或触发验证码。按优先级排列。

---

## 高优先级

### 1. 修复 UA 与浏览器版本不一致

**问题**：`puppeteer/index.ts` 中 User-Agent 硬编码为 Chrome 122，而 Puppeteer 实际下载并使用的是 Chrome 135，两者不一致是风控的常见检测点。`ZhihuApiService` 的 fetch 请求使用同一个硬编码 UA，也存在相同问题。

**方案**：Puppeteer 启动后，通过 `browser.version()` 读取实际浏览器版本，动态生成对应的 UA 字符串。`ZhihuApiService` 的请求头 UA 也应与 Puppeteer 保持一致，避免同一用户 Cookie 下出现两种不同 UA。

---

### 2. 修复请求头平台字段硬编码

**问题**：`ZhihuApiService` 的通用请求头中，`Sec-Ch-Ua-Platform` 硬编码为 `"Windows"`，但插件实际可能运行在 macOS 或 Linux 上，与真实系统不符。

**方案**：利用已有的 `PuppeteerManager.getOSType()` 方法，根据当前操作系统动态生成 `Sec-Ch-Ua-Platform` 的值（Windows → `"Windows"`，macOS → `"macOS"`，Linux → `"Linux"`）。

---

### 3. 停止主动移除 BEC Cookie

**问题**：`puppeteer/index.ts` 中会将 Cookie 里的 BEC 字段剔除后再注入页面。BEC 是知乎的行为验证 Token，主动缺失该字段本身就是风控信号。

**方案**：排查带 BEC 时发生跳转的根本原因，修复重定向处理逻辑，而不是通过删除 token 规避跳转。保留完整 Cookie 注入，在请求拦截层处理跳转响应。

---

## 中优先级

### 4. 修复异常的浏览器视窗尺寸

**问题**：Puppeteer 页面视窗固定为 `800x600`，该分辨率在真实用户中极为罕见，风控系统的统计模型会将其标记为异常。

**方案**：改为主流分辨率（如 `1280x800`、`1440x900`、`1920x1080`），并在启动时加入小幅随机偏移（±20px），模拟不同用户的设备差异。

---

### 5. 改进滚动行为的随机性

**问题**：`simulateHumanScroll` 每步间隔固定在 1000–1500ms，滚动距离也是固定值（1000px、-200px、1000px），行为模式过于规律，容易被行为指纹识别。

**方案**：引入更大的随机范围（如 500–3000ms），滚动距离也随机化。增加偶发性的短暂停顿（模拟用户驻留阅读），以及偶尔回滚后再继续向下的行为，使滚动曲线更接近真实用户。

---

## 低优先级

### 6. 侧边栏刷新增加冷却时间

**问题**：用户可以无限次快速点击刷新按钮，短时间内产生大量请求，触发知乎的频率限制，加速 Cookie 失效。

**方案**：为每个侧边栏列表设置刷新冷却时间（建议同一列表 30 秒内不允许重复触发），在冷却期间禁用刷新按钮并给出提示。

### 7. 连续 API 操作之间增加随机延迟

**问题**：`ZhihuApiService` 中收藏、投票、关注等操作是即时发出的，连续操作时呈现机器式的请求节奏。

**方案**：在连续多次 API 调用之间注入随机短延迟（200–800ms），避免请求时间戳呈现等间隔分布。

---

## 优先级汇总

| # | 问题 | 优先级 |
|---|------|--------|
| 1 | UA 与浏览器版本不一致 | 高 |
| 2 | 请求头平台字段硬编码 | 高 |
| 3 | 主动移除 BEC Cookie | 高 |
| 4 | 浏览器视窗尺寸异常 | 中 |
| 5 | 滚动行为随机性不足 | 中 |
| 6 | 侧边栏刷新无冷却限制 | 低 |
| 7 | 连续 API 操作无延迟 | 低 |
